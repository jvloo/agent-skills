# Validation record: prepared version 0.1.0

Date: 2026-09-09. Platform: macOS; execution tests used Python 3.9. Tests use synthetic
inputs and local fake CLIs, with no provider credentials or paid worker calls.

## Observed outcomes

- All 17 deterministic test methods pass for both packaged helper copies: literal quotes, shell-looking
  text, and Unicode survive stdin transport; logs and results use owner-only permissions.
- Successful execution with a structured `blocked` result retains separate runtime/task statuses.
- Nonzero exits, provider errors, absent completion, malformed/truncated output, and invalid
  handoffs cannot become accepted execution results.
- Deadline and cancellation tests stop same-group children, including a child that ignores
  SIGTERM, while retaining partial output. An unrelated process survives. A parent that exits
  with a live same-group child is incomplete and the child is cleaned up.
- Provider lifecycle regressions cover benign Claude notifications after a result, active/failed
  notifications, interrupted success envelopes, and new Codex tool activity after completion.
- Existing output directories and their contents are preserved by refusing reuse.
- Shared resources, package versions, and local links agree. Both skills pass the skill-creator
  validator; their result schemas also pass JSON Schema validation.

## Independent usage checks

An agent with a fresh context received a read-only request to check the two skill packages.
It identified their version and purpose, checked local references and schemas, and launched no
CLI worker. It was given the request and paths, not the expected evaluation checklist.

A separate agent that did not author the runner used the Codex skill with an explicitly supplied
offline test double, five-second deadline, and zero retries. It selected the bounded helper,
passed the contract on stdin, validated the structured handoff, and reported runtime success
separately from the fixture's blocked task. It correctly reported that the fake response was not
a substantive second opinion. This was an integration usage check, not a fresh-context model
quality comparison; that agent had previously edited the skill's instructions.

## Compatibility and limits

Claude Code 2.1.263 and Codex CLI 0.153.4 interfaces were inspected without generation. The
dated model-evidence references record the corresponding documentation and local catalog checks.
The deterministic fixtures establish helper behavior under those synthetic protocols, not real
provider authentication, billing, sandbox enforcement, live resume, or detached-job cancellation.
Linux execution support follows the same POSIX mechanisms but was not exercised on this host.

No no-skill/current/candidate task-quality benchmark or model-cost comparison has been run.
Do not claim measured quality uplift or optimal model routing from these checks. The baseline
method and additional scenarios are in [README.md](README.md) and [scenarios.json](scenarios.json).
