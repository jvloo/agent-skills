Both skills completed the progression from supplied-text consultation through parallel,
isolated worker implementation and controller reconciliation. The advanced first attempts
failed; success required one assisted configuration correction per provider. This report
preserves that distinction rather than treating final passing tests as first-pass reliability.

## Findings and corrections

1. **Actual schema incompatibility.** Claude rejected the bundled Draft 2020-12 declaration before
   model dispatch: `no schema with key or ref "https://json-schema.org/draft/2020-12/schema"`.
   Both packages now use Draft 7. Required fields, accepted values, and protocol `$id` are unchanged.
   Claude then returned a valid structured review; Codex's subsequent structured implementation
   also accepted the corrected schema. Packaging validation guards the compatible dialect.
2. **Claude file-rule construction.** The fresh controller built `Edit(/private/tmp/...)`, which
   did not authorize either assigned edit. The official grammar uses `//` for filesystem-absolute
   paths. Correcting only that prefix made both workers succeed with their exact-file restrictions
   intact. Added this non-obvious syntax to invocation guidance. See the
   [official file permission documentation](https://code.claude.com/docs/en/permissions#read-and-edit).
3. **Durable Claude sessions.** A sandboxed text call succeeded and returned an ID, but no resumable
   session was saved. An exact resume failed. Establishing normal session-store access fixed
   persistence; a newer decoy session did not interfere with exact-ID resume. Guidance now calls
   for persistence evidence when continuity matters, rather than relying on the returned ID alone.
4. **Codex non-Git resume.** The evaluation driver initially omitted `--skip-git-repo-check` on
   resume and was rejected before generation. Adding it preserved all restrictions and passed.
   The resume reference now repeats this relevant requirement explicitly.
5. **Overrestrictive temporary-state configuration.** The fresh Codex controller disabled `/tmp`
   and `TMPDIR` writes. Git's macOS launcher then emitted cache permission errors, and both workers
   obeyed the controller's broad stop condition without editing. Restoring ordinary workspace-write
   temporary-directory support allowed both workers to implement and run their assigned tests.
   Guidance now preserves normal temp support unless stricter confinement is actually required.

The original advanced runs correctly demonstrate that a successful CLI turn can contain a blocked
task. Claude workers made no edits. In the first Codex attempt the controller applied their proposed
fixes itself; that passing integration was **not** counted as worker implementation success.
The corrected Codex attempt started workers from the original base, and file-change events, scoped
diffs, and test output establish actual worker authorship.
